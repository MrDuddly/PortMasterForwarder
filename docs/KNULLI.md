# Knulli notes

> PortMasterForwarder is independent and **not affiliated with PortMaster** ([statement](INDEPENDENCE.md)).

> **PortMasterForwarder was developed and tested only on Knulli (Anbernic RG35XX H).** Everything else is **untested**.

## Compatibility

| Firmware / device | Status |
|---|---|
| **Knulli** on Anbernic RG35XX H | Developed and tested here |
| Other Knulli devices (RG35XX Plus/SP, RG40XX, RG28XX...) | Untested - expected to behave the same, not verified |
| Batocera, ROCKNIX, muOS, ArkOS, other EmulationStation-based systems | **Untested** - some paths and the launch command differ; no guarantees |
| Stock Anbernic firmware, OnionOS, Miyoo and similar | Not supported (different front-ends) |

The exact Knulli version used during development was not recorded; please state yours when you file an issue.
Compatibility reports for other setups are welcome (use the *Compatibility report* issue template) and will be added to a community table here.

## What has been verified on Knulli

These points come from the maintainer's hands-on testing on a RG35XX H while the tool was being developed. Anything not listed here has not been checked on real hardware.

- The generated **launcher scripts start PortMaster ports** from a category folder (the original script in `roms/ports` stays in charge).
- The generated **category systems appear** on the EmulationStation home screen and use the Art Book Next theme.
- In the Art Book Next theme the **GameCube icon key is `gc`** (not `gamecube`); `steam`, `ps2` and `wii` exist as well.
- `gamelist.xml` entries written by PortMasterForwarder (name, description, rating, release date, developer, publisher, genre, image) are read by EmulationStation; metadata scraped by
  EmulationStation for the PlayStation 2 category worked with the `ps2` platform value.

## What is assumed but not verified

- The `-system ports` argument in the generated command makes `emulatorlauncher` run the file exactly like the built-in *Ports* system. This follows the Batocera/Knulli
  design but was only confirmed through the behavior above, not by reading every Knulli build.
- The `platform` values used for scraping (`gamecube`, `ps2`, `pc`, `wii`, ...) are only relevant to EmulationStation's scraper; a wrong value just disables scraping for that category.
- Genres containing `/` (for example `Platformer / Platform`) may be split by EmulationStation's genre filters.
- Behavior with SD cards formatted in anything other than exFAT.

## How it works

### Launchers instead of copies or symlinks
Knulli's SHARE partition is normally **exFAT**, which has **no symlinks**, and copying large ports would waste space and break PortMaster updates.
For each game PortMasterForwarder writes a tiny shell script into the category folder:

```bash
#!/bin/bash
# generated by PortMasterForwarder
TARGET="/userdata/roms/ports/<Game>.sh"
if [ ! -f "$TARGET" ]; then
    echo "Original script not found: $TARGET"
    exit 1
fi
exec bash "$TARGET" "$@"
```

The original script is executed with `bash` (no executable bit needed on exFAT) and keeps using its own folder, so PortMaster's data and updates are untouched.

### Menu systems
For every category an overlay file `system/configs/emulationstation/es_systems_<folder>.cfg` is written (the supported way to add systems without touching the system image):

```xml
<systemList>
  <system>
    <fullname>PC</fullname>
    <name>portpc</name>
    <path>/userdata/roms/portpc</path>
    <extension>.sh</extension>
    <command>emulatorlauncher %CONTROLLERSCONFIG% -system ports -rom %ROM% -gameinfoxml %GAMEINFOXML% -systemname %SYSTEMNAME%</command>
    <platform>pc</platform>
    <theme>steam</theme>
    ...
  </system>
</systemList>
```

EmulationStation hides systems that contain no games, so a new category shows up after it receives its first game.

### Themes
The `<theme>` value selects the logo and artwork in Art Book Next. The picker offers friendly names (for example *GameCube (gc)*, *PC - Steam style (steam)*).
The list of valid keys is embedded in `core.THEME_KEYS`; PortMasterForwarder does not bundle any theme files.

## Undoing everything
- **Undo everything...** deletes the launchers and `es_systems_*.cfg` files that PortMasterForwarder created (files made by hand are kept unless you confirm).
- `gamelist.xml.bak` is the state of the file before PortMasterForwarder first changed it (only created if the file already existed).
- Games in `roms/ports`, PortMaster and the original systems are never modified. Images and gamelists are left in place by *Undo*.
- Back up your SD card before the first run.

## MCPE Launcher: one shortcut per installed version
Verified only on the RG35XX-H running Knulli (the maintainer's device); untested elsewhere.

- `extras/McpeLauncher.sh` is an adapted copy of the user's own MCPE launcher script. It accepts the version folder as its first argument
  (`bash McpeLauncher.sh "<folder in mcpe_launcher/versions>"`): an existing folder skips the menu, no argument shows the normal menu.
  Its button mapping is the maintainer's for the RG35XX-H; adjust it for your device. It contains a diagnostic `echo` to `launch_arg_log.txt` that can be removed.
- Rename it to exactly `McpeLauncher.sh` in `roms/ports` (a copy such as `McpeLauncher (2).sh` shows up as a separate game, and the shortcuts would call the old file).
- PortMasterForwarder creates one shortcut named `Minecraft <version>.sh` for each folder in `roms/ports/mcpe_launcher/versions/` that contains `lib/` or `assets/`
  (hidden/empty folders and names with `$ " \` or a backtick are ignored). Shortcuts whose version no longer exists are removed on APPLY, but only ones created by PortMasterForwarder.
- Metadata lookups for "Minecraft 1.2.3" search for "Minecraft". Turn the feature off with *One shortcut per MCPE version* in *Options*.
- The launcher script is not part of PortMaster and is not affiliated with it; check its own license before redistributing.
